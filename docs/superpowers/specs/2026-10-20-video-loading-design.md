# 商业作品集视频加载优化设计

## 目标

让商业作品集的视频首播体验接近原“让 AI 进入工作，也让 AI 进入创作”网站：用户点击后尽快播放，不再等待 GitHub Releases 跳转，同时保持现有页面内容、布局和竖屏比例不变。

## 已确认原因

- 当前商业版视频使用 GitHub Releases 地址，首次点击后才写入真实地址。
- `preload="none"` 使浏览器在点击前完全不建立视频请求。
- 首次播放需要重新连接、跳转、读取媒体信息并缓冲，造成明显等待。
- 原网站使用站内相对路径，并在页面加载阶段读取视频信息，链路更短。

## 方案

1. 将经过网页压缩的视频放入商业网站的 `assets/video/`，使用 GitHub Pages 同域相对路径。
2. 视频使用 `preload="metadata"`，提前读取媒体头；首屏外视频在接近视口时调用 `load()` 预热。
3. 保留海报，直到视频达到可播放状态；切换使用轻微透明度过渡，避免黑屏和突兀闪动。
4. 漫剧继续使用 `9:16` 容器和 `object-fit: cover`；横屏叙事影像继续使用 `16:9`。
5. 加载失败时继续显示海报和清晰错误提示，不破坏页面浏览。

## 范围

- 修改视频文件引用、预加载逻辑和必要的播放过渡样式。
- 不修改文案、图片、项目顺序、导航或视觉布局。
- 不修改另一个原始网站。

## 验证

- 本地检查所有视频路径存在、编码可被浏览器识别、HTML 不再引用 Releases。
- 桌面与手机尺寸检查横屏和竖屏比例。
- 发布后检查首页漫剧和各叙事项目：海报正常、点击可播、无横向溢出。
- 对比修改前后视频请求是否取消 GitHub Releases 重定向。

## 回滚

每个阶段独立提交。若发布后出现问题，可回退视频加载提交，恢复当前 Releases 地址与延迟加载逻辑。
